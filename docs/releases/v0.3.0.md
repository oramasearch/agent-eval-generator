### A model-written profile is checked before anything is written — #24

- The model's `profile_id` and table names were used as file paths, so a turn could write and delete outside its temporary folder in a pod every workspace shares (#21). `synthesize()` had no limit on tables or columns, so one turn could use up the pod's memory (#22).
- New `limits.check_profile()` runs right after parsing, in `service.run_turn`, in the batch command line and again in `synthesize()`. Names that become paths must match `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`; a profile has at most 12 tables, 64 columns per table, 128-character column names, no table declared twice, and at most 5,000,000 generated cells.
- A refused profile is answered `invalid profile: <reason>` and its trace graded failed.
- `records.package()` and `Table.write_jsonl()` resolve every path inside their directory and refuse one outside it; an old `records/` is removed only when it is a real directory inside the output folder, never through a symbolic link.

### The licence — #27

Everything in this repository that Orama wrote is under the MIT licence. Contributors sign `CLA.md` once. `THIRD_PARTY_LICENSES` lists every runtime dependency with its licence text; none is incompatible with MIT distribution.

## Known issues

Security-relevant first. All open at this tag.

1. #29 (release blocker for publishing): the image is built on `python:3.12-slim`, which bundles GPL and LGPL userland, so **the image is not published**. It is built and kept in the project's non-public Docker Hub repository until it moves to a scratch base with static binaries.
2. The public-tree cleanup (#28) is not in this release: the batch command line still uploads to the Hugging Face dataset named in the code, and some files still carry internal references. This tree is not the one to publish.
3. #6: the task's workspace is not passed explicitly on data-plane calls. Lake scopes the task credential to the task's workspace.

## Where it has run

**The v0.3.0 tree had not run on a development environment when it was released.** Lakes run the operator's default image of this agent; the changes since v0.2.0 are proven by the test suite only. Moving a Lake to `:v0.3.0` is a separate operator change.
